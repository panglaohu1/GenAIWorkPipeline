# Oskar 工作台配色方案

## 当前版本：晴朗青色（2026-10-05 用户反馈修订）

用户反馈上一版深导航、米灰与陶土组合显得陈旧，偏好登录页的明亮青色氛围。当前实现以此为准：工作面 `#F5FAFB`、卡片 `#FFFFFF`、浅青导航 `#E7F4F5`、Agent 展示区 `#DFF3F4`、主按钮 `#087F8C`、正文 `#193C46`。登录与系统页面共享 theme.css；作品截图不重新着色。只读与普通提示用浅青，警告/失败/通过仍使用独立语义色。

本版验证：正文/工作面 11.23:1，侧栏次级文字 4.77:1，白字/主按钮 4.75:1，展示区辅助文字 5.10:1；桌面和窄屏已检查。计算记录在 `artifacts/cyan-refresh-20261005/contrast.json`。

下面保留早期方案作为设计过程记录；其中的旧色值与深导航规范已被当前版本取代。

## 历史方案：海雾、石灰与陶土

2026-10-05 · 基于已融合公开研究的方法顾问方案 · 登录与系统工作台共用

此方案是本项目的原创 UI 配色，不是 Oskar 本人的设计、官方色板或从游戏截图直接采样的材质参数。本文读取了仓库的融合知识与当前前端，并查看 `docs/previews/oskar-agent.png`；没有重新浏览外部网页、观看原视频或声称新的媒体覆盖。

## 设计决策

采用暖浅灰工作面、冷石墨导航、低饱和海雾的 Agent 展示区、陶土色主要行动。系统应像一张摆在海边工坊里的设计桌：石材支撑内容，海水标识关系，屋顶色指出下一步，植被色只在需要表达健康与通过时出现。

这是一套明确的浅工作面方案，不跟随操作系统自动切换。深导航保留空间边界，作品审查使用中性灰底。暂不附加一套未经验证的全站暗色模式；若未来需要，逐组件建立第二套 token，并单独验收。

现有截图中，导航选中、Oskar 英雄区、主要按钮、知识提示、成功标记几乎都聚集在黄绿色。背景虽有明度层次，但语义角色被同一种气氛覆盖；用户很难一眼区分“当前所在”“可以执行”“质量通过”。绿色底与蓝灰作品卡也形成过强冷暖跳变。现有大量 8–11 px、低亮度的辅助文本进一步增加长时间阅读负担。

新方案的目标不是把绿色换成另一种满屏主题色，而是重新分配角色：多数区域保持安静，只有作品与下一步行动占据视觉焦点。

### 状态语义

| 状态 | 前景 | 浅底 | 使用方式 |
| --- | --- | --- | --- |
| 已通过、服务健康 | `--ok: #356A50` | `--ok-bg: #E4EEE6` | 实际记录通过才出现勾形与“已通过”；流程结束不能自动染绿 |
| 需要检查、待处理 | `--warn: #865612` | `--warn-bg: #F4E9CF` | 警告三角或明确文字，不用全屏黄色底 |
| 失败、交付阻断 | `--err: #A33F39` | `--err-bg: #F7E6E0` | 错误图标与具体原因；危险按钮默认用描边/文字，避免与陶土主行动混淆 |
| 等待审核、暂停 | `--wait: #67547D` | `--wait-bg: #EDE8F2` | 紫灰表示等待人工决定，与执行中区分 |
| 正在执行 | `--accent: #23626C` | `--selected-bg: #DEEAE8` | 进度符号与当前阶段，不复用警告黄 |
| 未验证、尚无结果 | `--muted: #5E7073` | `--panel-2: #E9EEED` | 空心圆与文字，不把未知渲染为成功 |

色彩只作为第二信号。失败/运行/通过/暂停要有文字及形状；选中页签要有底线或侧标记。陶土与错误红接近是刻意保留的材料关系，但必须用位置与组件形态区分：主行动是实心按钮，错误是带错误图标与说明的浅红信息块。

深导航里的状态不要直接使用这些深色前景。使用浅底状态小标签，或配专门亮色图标与明确文字。深底正文继续使用 `--nav-text` / `--nav-muted`，避免错误地沿用通用 `--muted`。

## 登录页

1. 顶栏、右侧登录表单使用纸白；左侧设计叙事区使用海雾。标题使用石墨正文色，强调词使用海水色。
2. 让场景本身讲述 Oskar：浅石材体块、海蓝底面、克制的陶土屋顶、灰绿植被。不要给插画套 sepia/hue-rotate，也不要给既有作品图着色。
3. Oskar 身份标签改为纸白卡，海水色字母/图标与深正文。当前大块荧光绿六边形取消；形状可以保留，颜色承担“Agent 身份”而不是成功状态。
4. 登录主按钮是这一屏唯一的大面积陶土块，白字。密码显示、来源介绍等次级动作使用海水链接或普通文本按钮。
5. 流程线用低饱和细线串联“研究—设计—构建—复盘”，当前可强调的步骤使用海水色。不要让每一步持续脉冲；尊重 reduced-motion，浮动幅度克制。
6. 输入框使用纸白/轻灰底及 `--control-line`，焦点为海水色 2 px 外环和 3 px offset。错误显示为表单内浅红说明块，不仅把边框染红。

## 工作台

- **侧栏**：深石墨，海水亮色选中标记。让“发起创作”的陶土主按钮成为明确行动入口；同一屏其他次要动作不复用实心陶土。
- **顶栏与资源栏**：纸白或浅工作面，用分隔线确定边界。资源面板不抢作品焦点；数值正文深色，告警按真实状态显示。
- **系统 Agent 页**：海雾英雄区，深正文；作品双联卡放在中性灰画框中。方法卡回到纸白，八组知识不分配八个竞争色，只用分类文字和少量标记。
- **任务详情**：当前阶段海水色、通过苔绿、失败砖红、等待紫灰。已有 mini-steps 的 `running` 不再使用 `warn`。质量结论跟实际证据走，运行状态与验收状态分开。
- **学习版本**：草稿/待审核紫灰，当前启用版本海水，创建成功提示苔绿。避免把“草稿生成了”渲染为“Agent 能力已经提升”。
- **作品审查**：图片与模型所在卡片使用中性灰背景，无彩色渐变、mix-blend-mode、全局滤镜或染色阴影。不同版本同一检视底色与同一机位；界面配色改动不能宣称改善了作品。

面积以近似 75% 的纸白/暖浅灰、20% 的冷石墨/海雾结构区、5% 的功能强调色为方向，不作为精确 KPI。真正的重要规则是：不要为凑比例把绿色或陶土涂满非行动卡片。

## 对比度实算

计算采用 sRGB 转线性后的相对亮度：分量 `c ≤ 0.04045` 时 `c/12.92`，否则 `((c+0.055)/1.055)^2.4`；`L = 0.2126R + 0.7152G + 0.0722B`；对比度为 `(L较亮+0.05)/(L较暗+0.05)`。下列值为本地脚本实际计算，保留两位小数。本方案以普通文字至少 4.5:1、需要辨认的控件边界至少 3:1 作为验收目标。

| 前景 / 背景 | 比值 | 用途 |
| --- | --- | --- |
| `#273B40` / `#F2F1EB` | 10.39:1 | 主工作面正文 |
| `#273B40` / `#FCFBF7` | 11.36:1 | 卡片正文 |
| `#5E7073` / `#FCFBF7` | 5.02:1 | 卡片辅助文案 |
| `#5E7073` / `#F2F1EB` | 4.59:1 | 工作面辅助文案；禁止继续降低透明度 |
| `#526569` / `#DCE7E5` | 4.85:1 | 英雄区辅助文案 |
| `#E7EEEC` / `#23343B` | 10.97:1 | 深导航正文 |
| `#ADC0C1` / `#23343B` | 6.82:1 | 深导航辅助文案 |
| `#93C4CA` / `#2F4951` | 5.01:1 | 深导航选中强调 |
| `#FFFFFF` / `#A94E37` | 5.48:1 | 主要行动 |
| `#FFFFFF` / `#903E2B` | 7.22:1 | 主要行动悬停 |
| `#23626C` / `#FCFBF7` | 6.68:1 | 浅底链接与焦点 |
| `#23626C` / `#DEEAE8` | 5.61:1 | 选中标签 |
| `#356A50` / `#E4EEE6` | 5.31:1 | 成功状态 |
| `#865612` / `#F4E9CF` | 5.19:1 | 警告状态 |
| `#A33F39` / `#F7E6E0` | 5.21:1 | 错误状态 |
| `#67547D` / `#EDE8F2` | 5.55:1 | 待审核状态 |
| `#73878A` / `#FCFBF7` | 3.65:1 | 交互控件边框 |
| `#CAD3D1` / `#FCFBF7` | 1.48:1 | 仅装饰分隔线，不作为控件边界 |

特别注意：通用 muted `#5E7073` 放在海雾底 `#DCE7E5` 仅为 4.11:1，不能直接沿用；这正是单独设置 `--hero-muted` 的原因。对比度通过不等于可读性完全通过：中文正文建议 13–14 px，核心表格/导航至少 12 px，日期与非关键元数据尽量不低于 11 px；8–9 px 的全大写英文装饰标签不能承载操作必需信息。

## 实施建议

1. 新建共享 `theme.css`，在登录与工作台中先于组件样式加载；统一 token、`color-scheme: light`、焦点及状态基本样式。
2. 删除 `workspace.css` 中强制绿色的双 `:root` 覆盖，处理 `style.css` 的系统自动浅色媒体查询，避免同一 token 有三套互相覆盖的定义。
3. 不做全局十六进制一对一替换。现有同一个绿色常被用作正文、成功、按钮和边界，应按组件语义分别迁移。`--accent` 表示海水选择/链接，`--accent-2` 保留为旧按钮兼容别名并映射陶土。
4. 深侧栏采用局部变量作用域或明确 `--nav-*` token；纸白主面不要继承侧栏的浅字色。placeholder、disabled、标签、图标都要逐项检查。
5. 将 `.dot.running`、`.mini-steps i.running`、`.step.running` 迁到“执行中”语义，而不是继续引用 `--warn`。检索 JS 内联颜色，避免只迁移 CSS。
6. 优先验收登录、Agent 页、任务质量页、学习/新增 Agent 对话框，再覆盖日志、服务管理、作品查看器和空状态。
7. 实际页面应检查 1280 px 桌面、窄屏、键盘 focus、表单错误、长中文标题、无结果和禁用状态。至少保留登录及 Agent 页的前后截图；颜色和布局验收不能只靠单元测试。

固定边界：不修改作品图原文件，不制造作者肖像或冒用作者口吻，不把这份 UI 色板自动写成所有风格 Agent 的创作色板。Oskar 为工作台提供设计方法，未来的其他 Agent 仍应保留自己的作品风格。

## 多 Agent 的身份扩展

系统外壳和状态语义不随 Agent 改变：成功绿始终只表示健康或验证通过。每位 Agent 通过名称、专长、独立几何印记和真实作品卡表达身份；可增加一枚受控的身份色签，但不能改写全局 `--ok` / `--err` / `--action`。Oskar 的海雾展示区是当前 Agent 的视觉介绍，不代表未来每个 Agent 都应使用海雾背景。为新 Agent 增加身份底色时，同步配置能通过对比度验收的正文与辅助文字，禁用随机颜色和仅靠颜色区分 Agent 的做法。

“邀请 Agent 修改现有项目”应在项目页显示明确的受邀 Agent、规则版本与作用范围。主行动仍是统一陶土色；当前参与者用名称/印记及海水选中状态表示。设计师研究来源与生成的 Agent 身份需要分开陈述，不能暗示真实设计师本人正在参与或授权。
