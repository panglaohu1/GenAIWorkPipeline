## 一、他的方法到底是什么（学习笔记）

Oskar 自己说「十年来一直在做同一件事，每次做一个小东西」。演进路线是：BrickBlock（原型，确立不规则几何上的 marching cubes）→ Bad North（300+ 模块的 WFC 岛屿）→ Night Call（不规则网格贴合巴黎街道）→ Townscaper（三者合一、实时交互）。核心可以拆成四层。

### 1. 不规则四边形网格（Townscaper 招牌外观的来源）

| 步骤 | 做法 | 关键参数 |
|---|---|---|
| ① 种子点 | 六边形同心环点阵（Oskar 原版，保留淡淡的六边形记忆）；或 Poisson 盘采样（更各向同性） | 六边形半径 N 格 |
| ② 三角化 | 六边形点阵直接连成三角扇（或 Delaunay） | — |
| ③ 随机合并 | 随机挑选相邻三角形两两合并成四边形；只接受凸、内角在 [36°,162°] 的四边形；合不上的三角形留着 | 随机种子 |
| ④ 全部细分 | 每个面（三角形→3 个、四边形→4 个）按「角点 + 两条边中点 + 面中心」切成小四边形，**此后 100% 是四边形** | 边中点按边去重，保证无缝 |
| ⑤ 松弛 | 迭代让每个四边形趋近正方形（闭式求最近正方形的旋转角 α，累加各顶点受力 × 拉力系数） | 拉力 0.3、约 100 次迭代（或 Oskar 原版：每个顶点移向与邻点等距的位置） |
| ⑥ 取对偶 | 每个内部顶点周围所有四边形的中心点按角度连起来 → 对偶格（软六边形/五边形/四边形），**玩家点的是对偶格** | — |

### 2. 双网格 + 角点状态（marching squares / cubes）

- **状态存在「角点」上**，不存在格子里：每个网格顶点记一个值（有/无，或层高、材质）。
- 点一个对偶格 → 翻转它包围的那个角点 → 周围最多 4 个四边形重新选模块。
- 一个四边形由 **4 个角点**决定：2⁴=16 种，在正方形的 8 种对称（4 旋转 × 2 镜像）下只剩 **6 种基本形**：空、凸角、直墙、对角（鞍形，要约定一种连法）、凹角、满。
- 叠层后变成 marching cubes（2⁸=256 → 对称后一小组）；但 Oskar 实际是 **2.5D**：每层用 2D 的 6 种形，外加上下连接件。
- **模块是「角段」不是整栋房**：这是能塞进任意歪斜格子的关键。

### 3. 模块形变（手工美术贴进歪格子）

- 每个模块在**单位立方体 [0,1]³** 里手工建模，顶点存成 (u,v,w) 参数。
- 放置时用格子 8 个角点做**三线性插值**：底面 4 角按 (u,v) 插值 → p0，顶面 4 角 → p1，再按 w 插值。
- 相邻格子共享角点 → 形变后边界顶点落在同一位置 → **天然无缝**。歪斜全在形变里，模块本身永远是规整的。

### 4. WFC（波函数坍缩）与装饰

- **邻接约束从模块边缘自动扫描得出**（Bad North：在建模软件里建好，导入引擎时扫描每个面的边缘，自动算出谁能挨着谁）；另有一张「排除表」手动禁止视觉上不搭的组合。
- 每个格子初始是「所有模块都可能」→ 选熵最低的格子坍缩 → 约束向邻居传播 → 失败时保存状态重启（Bad North）或静默放过（Townscaper）。
- Bad North 还编码了**可通行层**（单位能不能走进走出），防止生成走不通的岛。
- **硬约束和装饰分两阶段**：先用 WFC 定结构，再做装饰。
- **配方（recipes）**：特殊图案（拱门、楼梯、花园、大屋顶）优先级最高，但只在邻接严格匹配时出现；比如花园只出现在「靠墙 + 完全围合」的空地。
- 用他的话说：**玩家掌控大形，我在小形上玩花样**。

### 5. 美术规则

- 一套统一的模块库胜过多套换皮（他拒绝做日式或未来主题，就是为了保证美学统一）。
- 抽象、适度细节：留给玩家想象空间；细节密度要兼顾缩小后的锯齿。
- 窗户在放置后用模板缓冲切出（避免模块边角处窗户穿帮）。
- 相邻模块禁止完全相同或镜像，避免重复感。
- 小生命：蝴蝶、鸟挂在附近物体上，偶尔飞起。
- 清晰的剪影与描边；有限调色盘 + 每块明度微抖；落块时有弹性 plop 动画。
- （TigerMessenger 已有研究补充：15 色调色盘、同一竖列同色为一户、屋顶瓦色统一、窗户统一深色、双片交叉灌木、晾衣绳。**你的偏好：不要红旗点缀**。）

## 二、为什么这条路对我们的流水线很合适

对照 P0/P1 的教训：

| 现在的痛点 | Oskar 式引擎怎么解决 |
|---|---|
| LLM 用 10–40 个几何体「雕」物体，形状不准、部件悬空 | 几何全部来自**手工模块库**，LLM 不再摆坐标，悬空和穿插在结构上就不可能发生 |
| 风格不统一，每个资产各长各的 | 一套模块库 + 一套调色盘 + 统一描边 → 天然风格一致 |
| 补丁迭代收益低（16% 的轮次有进步） | 状态空间很小（角点开/关、层高、材质、配方），每一步都是离散、可回退的小改动 |
| 评审打分不可靠 | 目标图也按同一风格生成后，客观相似度更有意义；硬检查（连通、可通行）由规则保证 |
| 复杂场景拆分难 | 场景本身就是「网格 + 角点状态」，拆分 = 在网格上涂出区域 |

**Bonsai 的角色变成「风格器 / 导演」**：读目标图 → 输出一张**角点状态图**（哪里有建筑、几层、什么材质、哪里放配方），外加少量参数（网格种子、调色盘）。几何、形变、装饰、拼接全部由确定性引擎完成。这正是你说的「给 Bonsai 配一个风格器那么简单」。

## 三、引擎设计草案（Blender 端实现）

```
① 网格层     hex 点阵 → 随机合并 → 细分 → 松弛 → 对偶格（Python，确定性，按种子缓存）
② 状态层     每个角点：高度 h(0..N)、材质 id、标志（水/地/路）
③ 模块库     在 Blender 里手工/半程序化建好：6 种基本形 × 每层类型（地基/墙/屋顶/顶层）× 2–3 个变体
             + 配方模块（拱门、楼梯、花园、塔尖……）；每个模块存 (u,v,w) 顶点、边缘标签
④ 选择层     逐格读 4（或 8）个角点 → 基本形 + 旋转/镜像 → 变体（按格 id 做种子）
             → 配方匹配（优先级表）→ 需要时用 WFC 解邻接约束（装饰层、Bad North 式地形）
⑤ 形变层     三线性插值把模块贴进歪格子 → 合并网格 → 调色盘上色（每块明度微抖）→ 描边
⑥ 导出层     GLB → Godot（现有 Kit 与接入闸门不变）
```

LLM（Bonsai）接口：一个很小的 JSON，例如
`{"seed": 7, "palette": "harbor", "cells": [{"at": [q, r], "h": 3, "mat": "plaster_warm"}, …], "recipes": [{"type": "arch", "at": [...]}]}`
→ 引擎渲染 → 客观评分 + 看图 → Bonsai 只改少量格子 → 再渲染。

## 四、需要你决定的事

1. **风格统一到什么程度**：所有游戏（包括水晶城、湖沼这类莫比斯风格的场景）都改用这套 Townscaper 式模块语言吗？还是只用于城镇和建筑类资产，有机物（树、岩、水晶）另走 P2 图生 3D？
2. **模块库从哪来**：模块是整个风格的灵魂。可选：(a) 我先用程序化方式建第一版（规整、够用）；(b) 你或美术手工建；(c) 两者结合：程序化打底，再逐步替换成手工模块。
3. **动图资料**：你在右侧内置浏览器里登录 X 之后告诉我，我逐条看他的开发动图，把细节（配方、动画节奏、材质和光照）补进本文。
